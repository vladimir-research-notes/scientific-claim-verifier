Example report

A real verification result for a dataset-statistic claim, printed by claimverifier verify. The Markdown/HTML report generator lands in Milestone 9; the content below — the five separated channels and the trace behind them — is what it will render.

Verification result

$ claimverifier verify --task tasks/statistical_claims/dataset_mean.yaml

Task            : dataset_mean
Claim           : c_dataset_mean (dataset_claim)
Text            : The measurements dataset has 12 samples with a mean value of 3.4.
Normalized      : mean ~ 3.4

Supporting text (retrieved evidence):
  "The measurements dataset has 12 samples with a mean value of 3.4."

Computed checks (what each artifact says about the claim):
  [pass        ] evidence_presence  p_dataset        -> supports
  [pass        ] dataset_statistic  ds_measurements  -> supports
  [pass        ] dataset_statistic  ds_measurements  -> supports

Inference (drawn from the checks above; each rule names the checks it read):
  support_label       : supported
    rule              : all_checks_support [c_dataset_mean.evidence_presence.1,
                        c_dataset_mean.dataset_statistic.1,
                        c_dataset_mean.dataset_statistic.2]
    because           : all 3 check(s) reached a verdict and every verdict supports the claim
  reproduction_status : reproduced
    rule              : dataset_recomputation
    because           : the recomputation reproduced the claimed value exactly
  failure_mode        : none
    rule              : clean
    because           : the artifacts support the claim and nothing failed to reproduce
  confidence          : 1.00 (share of checks that reached a verdict; not a probability)

Unverifiable from these artifacts (what this verdict does NOT settle):
  (none — every check reached a verdict)

Task gold       : supported [ok ] / reproduced [ok ] / none [ok ]

Two dataset_statistic checks, not one: the claim asserts a mean and a sample count, and each is recomputed from the committed CSV independently — the mean within the claim's own reported precision (±0.05, because it was written 3.4), the count exactly, because a CSV has a whole number of rows.

The trace behind it

--out DIR writes <task_id>.result.json and <task_id>.trace.jsonl. Every inference names the rule that produced it and the checks that rule read, so a reader can re-derive the verdict without re-reading the code:

{"data": {"claim_id": "c_dataset_mean", "claim_type": "dataset_claim", ...}, "kind": "scoring.claim", "seq": 0}
{"data": {"links": [...]}, "kind": "scoring.evidence", "seq": 1}
{"data": {"check": {...}, "signal": "supports"}, "kind": "scoring.check", "seq": 2}
{"data": {"check": {...}, "signal": "supports"}, "kind": "scoring.check", "seq": 3}
{"data": {"check": {...}, "signal": "supports"}, "kind": "scoring.check", "seq": 4}
{"data": {"because": "all 3 check(s) reached a verdict...", "check_ids": [...],
          "rule": "all_checks_support", "support_label": "supported"}, "kind": "scoring.support", "seq": 5}
{"data": {"because": "the recomputation reproduced the claimed value exactly",
          "reproduction_status": "reproduced", "rule": "dataset_recomputation"}, "kind": "scoring.reproduction", "seq": 6}
{"data": {"causes": [], "failure_mode": "none", "rule": "clean"}, "kind": "scoring.failure", "seq": 7}
{"data": {"confidence": 1.0, "limitations": [], "schema_version": "1.2"}, "kind": "scoring.result", "seq": 8}

Keys are sorted and nothing is read from the wall clock, so two runs of one task produce byte-identical bytes — including tasks whose script actually executes.

Report sections

Every report keeps the five channels separate — extracted claim, supporting text, computed check, inference, unverifiable — plus limitations and a link to the JSONL trace. A verdict is not a summary of the checks; it is an inference from them, and both are shown so a reader can disagree with the second without losing the first.

Milestone 9 renders this as Markdown (and optional HTML) directly from the trace, and Milestone 8's smoke suite will link a generated report for every task. See the Results page for the fixture where this pipeline declines to reach a verdict at all.
