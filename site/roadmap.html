Roadmap

Directions beyond the initial milestones — deliberately modest and honest. Nothing here requires paid APIs or GPUs.

Integration contracts (Milestone 11 — built)

Rather than depending on sibling projects, this repo defines its own export contracts so it can plug into them later. All five are live behind claimverifier export; see Integrations. No external schema was consulted, so these are contracts shaped for a consumer role, not adapters validated against those projects.

code-agent runtime

runnable-tasks: each task as argv plus hashed input files and a success criterion, and a written guarantee about the JSONL trace shape.

BioScientist OS

evidence-records: each verification as a structured record with the five audit channels as five sibling keys.

BioAgentBench

benchmark: the smoke suite (11 tasks) with per-task predicted-vs-gold scoring, and a declared primary metric — wrong_verdicts, lower is better.

LLM regression / observability

metrics: per-run scalars and labels over a fixed key space, plus a reference compare() that flags only real regressions.

agent-control-bench

episodes: claim verifications as controllable, replayable units — claimverifier replay re-runs all eleven and reproduces every verdict.

The research path (Milestone 12 — written)

docs/PAPER_PATH.md sets out what would have to be true before any of this repo's numbers were a claim about the world rather than a claim about this repository. The short version: this is a systems and auditability contribution, not an NLP result. The instrument is finished enough to be pointed at something; the paper is the corpus, the baselines, and the ablation — not the instrument.

Three studies, in dependency order, none of which needs a GPU or a paid API:

1. A real, annotated claim set

Claims from open-access papers with released artifacts, hundreds not dozens, two annotators each, inter-annotator agreement reported. Until this exists, every accuracy-shaped number here is a self-report.

2. Baselines

10/11 is unanchored. A system labelling everything unverifiable_from_artifacts scores zero wrong verdicts — the declared primary metric. That degenerate floor must be reported alongside.

3. The falsifying ablation

Collapse check status into claim signal and measure the induced wrong verdicts. If they do not appear, this repo's central design claim is wrong and should be withdrawn.

The transferable argument is about evaluation design: for verification systems, an evaluation that cannot distinguish asserting something false from declining to assert will systematically select for models that guess. Its honest counterweight, stated in the same document: a metric that only punishes wrong verdicts is gameable by silence, so wrong_verdicts and conservative_misses must always be reported together, and never summed.

Method directions

Deliberately modest, and ordered by priority in docs/PAPER_PATH.md §5. Each keeps the rule-based path as the interpretable floor.

  • A stronger evidence check with an exact target: move synthetic_data_passage from inconclusive to pass without moving contradicted_f1's passage check off pass.
  • figure_recompute: the CheckType and the figure linker exist; no check and no fixture do. Figures carry data series, never pixels, so this is a recomputation — not a vision problem.
  • Semantic claim conditions — the one extraction field the pipeline misses today, and the field that separates underspecified from supported.
  • Cross-claim consistency. Every claim is scored independently; a paper contradicting itself across sections is the most interesting object this tool could find, and it currently cannot.
  • Distributional and seed-sensitivity checks: a metric that holds only for one seed is a reproducibility failure numeric_tolerance would call a pass.
  • Optional, cost-guarded LLM adapters for extraction assistance — with the rule-based path always available and always the default.

What will stay out

The safety boundaries are permanent: no clinical/medical advice, no wet-lab protocols, no dual-use biology, no real patient data, and no claim to be a production untrusted-code sandbox. See Safety and Limitations.

A verdict is relative to the supplied artifacts. That is not a limitation to be engineered away — it is the thesis.
