The round trip is the result. docs/PLAN.md §11 requires that reports be generated from traces, and the only thing separating that from a slogan is a test that fails when it stops being true. So a test scores every committed fixture, writes its trace, reads it back through the reader, and asserts the reconstructed Milestone 7 ScoredClaim equals the original. A trace that cannot be turned back into the verdict it recorded is not an audit record — it is a log.

Making that pass required changing the trace, not the reader. RunTrace.to_jsonl serializes events only, so a trace's run_id, task_id, and bundle_id survived nowhere but the filename, and scoring.claim recorded five of the extracted claim's fields rather than all of them. SCHEMA_VERSION moved to 1.3: a scoring.run event now opens every stream, scoring.claim carries the whole claim, and a pre-1.3 trace is refused by name with an instruction rather than guessed at. No model changed.

Twelve of the 98 tests are about refusing to render: a truncated, reordered, duplicated, schema-violating, foreign (sandbox.*), non-JSONL, empty, missing, or wrong-major-version trace raises ReportError naming the file, rather than producing a plausible-looking report. Every object is re-validated through its pydantic model on the way in.

See the Example report for the full text of contradicted_f1, the fixture whose abstract asserts a number its own table denies — and which the report keeps in two different sections.

The suite is a gate, not a scoreboard

run-suite exits non-zero when the pipeline regresses, and the definition of regression is deliberately asymmetric:

  • Any wrong verdict — a committal support label the task's gold outcome disagrees with — fails the run. tasks/smoke_suite.yaml has no key that could declare one acceptable, so a suite file can never bless one. (A test asserts the schema rejects the field outright.)
  • A conservative miss — predicting unverifiable_from_artifacts where gold commits — fails the run only if the set of them changed. A new one is a regression; a fixed one must be removed from the file rather than left to rot.
That asymmetry is the point. A change that raises label accuracy by turning a claim the pipeline honestly declined to decide into one it decides wrongly has made the tool worse, and a single accuracy number would have called it an improvement. The gate is tested by injecting each failure in turn — a wrong verdict, a new miss, a stale declared miss — and asserting it fails; a gate that never fails proves nothing when it passes.

A suite full of contradicted claims exits 0: finding a contradiction is the tool working. And --no-execute does not gate at all — skipping the fixture scripts leaves every code-reproduction claim undecided by its own artifacts, and the gold outcomes it would be judged against assume the scripts ran. Reporting those label shifts as "wrong verdicts" would blame the pipeline for the operator's flag.

What is byte-reproducible, and what is not

Two runs of the suite into two different directories produce byte-identical *.trace.jsonl (all 11), summary.csv, and summary.json. Exactly two artifacts differ, in exactly one field each, and both are paths the caller chose: <task_id>.result.json records its own trace's absolute trace_path, and summary.txt names the output directory. summary.csv refers to each trace by filename alone, so it stays portable. A test hashes every artifact of two runs and diffs the two exceptions field by field.

The only number that matters here

Wrong verdicts: 0. A mismatch is bucketed by kind, because a single accuracy number hides the difference between a system that says the wrong thing and one that declines to say anything. A conservative miss predicts a non-committal label where gold commits — the system declined to decide, and asserted nothing false. A wrong verdict asserts a committal label gold disagrees with.

The pipeline's single miss is synthetic_data_passage, and it is conservative. Gold says supported, and the passage really does support the claim. But "The model is trained only on synthetic data" is asserted by "All experiments use synthetic data …; no real corpora were used at any stage of training" — a paraphrase at 40% token coverage. The lexical evidence check returns inconclusive, scoring maps that to unverifiable_from_artifacts with failure mode evidence_undecidable, and confidence reads 0.00: nothing about this claim was decided, and the report says so.

This is the honest cost of a transparent method, and wrong_verdicts is the number to watch: a change to the extractor, the linker, or the checks that raises label accuracy by turning a conservative miss into a wrong verdict has made the tool worse.

How to read this

A regression harness, not a benchmark. Eleven hand-authored synthetic fixtures, whose gold outcomes were written alongside the rules that score them. 10/11 does not mean scientific claim verification is 91% solved. What the table shows is that the rule table is coherent (no fixture needs a special case), that it never asserts a verdict gold contradicts, and that the one claim its methods cannot read is reported as unread rather than guessed at.

The four fixtures added in Milestone 8 are the closest thing here to a held-out test: they were authored after the Milestone 7 rule table was frozen, and each landed on its hand-written gold outcome without a single change to the extractor, the linker, the checks, or the rules. That is weak evidence — the same agent wrote both, with the rules in view — but it is stronger than the seven that came before, where the rules were tuned as the fixtures were written.

reproduction_status is 11/11 across all six statuses it can reach: three fixtures reproduce exactly, dataset_std reproduces approximately (pstdev = 1.1298967…, inside the ±0.05 its one-decimal claim admits but not on it), dataset_mean_overstated fails numerically, unreproducible_accuracy fails environmentally, and the five table and passage claims correctly get not_applicable: reading a value out of a table cell is a lookup, not a reproduction. Traces are byte-identical across runs, including for the three fixtures whose scripts actually execute. See docs/SCORING.md.

reproduce_from_predictions.py (Milestone 8) is a complete, working script whose input predictions.csv the paper never released — the most ordinary reproducibility failure there is. The sandbox reports exited 1, code_execution records error / nonzero_exit, and the reproduction status is failed_environment — never failed_numeric_mismatch, because a script that will not run tells you nothing about the claim's number.

The Milestone 5 check table was unchanged by the new runner when it landed, and that is the result worth reporting: swapping a bare subprocess.run for a policy-enforcing sandbox moved no verdict. The ScriptRunner protocol held, and code_execution changed only its default runner.

Each guard below is exercised by a test that fires it. These are reproducibility controls, not a security boundary.

The result that took two attempts. The first network guard replaced socket.socket with a function. ssl.py executes class SSLSocket(socket) at import time, so import urllib.request died with TypeError: function() argument 'code' must be code, not str — blocking the network by accident, in a way that would have confused anyone whose script merely imported http.client. The guard now installs a raising subclass, so the import succeeds and the denial happens at socket.create_connection, where the connection is actually attempted. Both behaviours are test-pinned.

How to read this. Three fixtures is not a reproducibility benchmark. The scripts are stdlib-only, embed their own data (or, in the failing case, deliberately do not), take no arguments, and were written by the same agent as the sandbox that runs them. What the table shows is that the controls hold and cost nothing. The interesting failures are the guard rows, not the two passes. Wall-clock duration is measured (≈30 ms per script) and deliberately kept out of the trace unless --with-timing is passed — it is the only value in an execution record that cannot be reproduced.

evidence_presence fails on negated_training_data and is inconclusive on synthetic_data_passage, and the difference is the whole design: the first passage contains every token of its claim and a negation, which refutes it; the second is a paraphrase the rule cannot read, which refutes nothing. unreproducible_accuracy is where error and skipped come from, and they are not the same thing: the script exited 1, so code_execution could not run the claim's computation, and numeric_tolerance is then skipped, not fail — no number disagreed with 0.95, because no number exists.

The two rows that matter.

contradicted_f1 — the fixture the project exists for. The abstract states "Method B reaches an F1 score of 91.0 on MNLI" verbatim, so evidence_presence passes. The results table reports 86.0, so table_value fails. Both are correct, and a system that collapsed them into one verdict would destroy the only interesting fact about the claim: the paper contradicts its own table.

synthetic_data_passage — the check admitting it cannot decide. Gold says supported, and the passage really does support the claim. But "the model is trained only on synthetic data" is asserted by "no real corpora were used at any stage of training" — a paraphrase. Token coverage is 40%: trained ≠ training, and only ≠ no real corpora were used. A bag-of-words rule cannot bridge that, so the check returns inconclusive, not fail. This is the honest cost of a transparent method, and it is the number to watch: a stronger evidence checker is measured by whether it moves this claim to pass without moving contradicted_f1's passage check off pass.

How to read this. A consistency check, not a benchmark. Meanwhile its distractor's strongest word never counts: corpus does not match corpora, so morphology costs the runner-up most of its overlap.
