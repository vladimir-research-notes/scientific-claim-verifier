Claim schema

A claim is not free text to be summarized — it is a typed object with explicit, checkable fields. This lets checks target specific values and lets the report separate the claim from the evidence and the inference.

The canonical, field-by-field definition lives in docs/CLAIM_SCHEMA.md, written to match the pydantic models in schemas.py so the docs and the code cannot drift. Every model forbids unknown fields (extra="forbid"), and the vocabularies below are StrEnums whose values are exactly the strings shown here.

Rule-based extraction (Milestone 3)

The claim as authored carries only an id, its text, its type, and provenance. The RuleBasedClaimExtractor populates the rest of the fields above from the claim text and its artifact bundle. It is regular expressions plus small closed lexicons — no learned NLP, no parsing, no inference — and it is labelled a heuristic everywhere it appears. What it buys is the property this project exists for: every populated field is produced by a named rule, and the rules that fired are recorded, so a reviewer can see exactly why a value was extracted.

FieldRuleChannel
expected_valueThe "to" value of from X to Y, else the first numeric token that is not a sample count.reliable
baseline_valueThe "from" value of from X to Y. Nothing else sets it.reliable
comparison_operatorfrom X to Y direction → comparison verb → claim-type default (~ for recomputation claims, = for a plain numeric claim).reliable
unitsA % sign, or a percentage-scale metric whose value exceeds 1.reliable
metricsA closed surface-form → canonical-name lexicon, on word boundaries.reliable
datasetsA known-name lexicon plus the phrase <name> dataset.best effort
entitiesA Method X pattern plus a minimal role lexicon.best effort
conditionsSample counts only (n = 12). Semantic conditions are not guessed.best effort

Two rules carry most of the weight. Digits inside identifiers are not numbers, so the 2 in SST-2 never becomes a value. And an integer followed by a count noun is a count, not a headline value, so "12 samples with a mean of 3.4" extracts 3.4.

The rules are deliberately conservative: they prefer to leave a field empty over guessing. An unextracted field is scored underspecified downstream, which is an honest outcome; a confidently wrong field is not. On the six committed fixtures the extractor recovers seven of the eight scored fields on every task, and conditions on five of six — the miss is a free-form semantic condition it declines to guess. See Results and docs/EXTRACTION.md.

normalized_claim is the extractor's own canonical notation (accuracy: 72 -> 78 (>) %). It is deliberately not scored against a task's hand-authored gold string: a rule-based system cannot be expected to reproduce arbitrary phrasing, and scoring it as if it could would be overclaiming. Searching the bundle for the passage that best supports a claim — with a relevance score — is the evidence linker's job (Milestone 4); the extractor only records references the claim text names explicitly, and leaves evidence_links empty.

Check outcomes (Milestone 5)

A VerificationCheck carries a CheckStatus. There are five, because the ways a check can fail to say "yes" mean different things to scoring:

StatusMeaning
passThe check ran; the artifacts agree with the claim.
failThe check ran; the artifacts disagree.
inconclusiveThe check ran; its method cannot decide.
errorThe check itself could not run.
skippedThe check did not apply.

inconclusive was added in Milestone 5 (schema version 1.1, additive: every 1.0 document stays valid). Without it, a transparent lexical check faced with a paraphrase would have to report fail, and scoring would manufacture a contradiction out of the checker's own ignorance. See Checks.

Design intent

  • Every field a check needs is explicit — no re-parsing the claim text at check time.
  • Extraction may be heuristic; the schema is where heuristics are made auditable.
  • An unsupported_or_contextual_claim is a first-class outcome, not an error.
  • "I cannot tell" is a first-class outcome too — it is never rounded to "no".
