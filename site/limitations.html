Limitations

Being explicit about limits is part of the auditability goal. This system is a small, honest tool — not an oracle.

Verdicts are relative to the artifacts

Every support label and reproducibility status is relative to the supplied bundle. "Supported" means the artifacts in the task back the claim, not that the claim is true in the world. There is no universal scientific-truth judgment.

Extraction is heuristic

The default claim extractor is rule-based and deliberately simple. It targets numeric and comparison claims in clean text and will miss or mis-parse complex phrasing. It is a transparent baseline, not a state-of-the-art NLP system, and is labelled as such everywhere.

The evidence check cannot confirm a paraphrase

Deciding whether a passage asserts a claim is done lexically: verbatim containment, or every content token of the claim present with matching polarity. It has no model of morphology or synonymy — trained does not match training — so a passage that supports the claim in different words is reported inconclusive, not pass. One of the eleven committed fixtures lands there, and that is the correct answer for this method rather than a bug: the alternative is to guess. Negation cues are a closed set of function words, so contractions (doesn't) are not detected, and verbatim containment is not polarity-checked. Polarity is read from the passage's best-matching sentence, so a negation that lives in a different sentence than the claim's tokens would be missed; no fixture covers that case. See Checks.

Fixtures are small and synthetic

Fixtures are tiny, synthetic or open datasets chosen to exercise the checks. They are not representative of real papers at scale, and results should not be read as a benchmark leaderboard. The locator conventions and the table row rule were written with the committed table fixtures in view, so a perfect linking score is a consistency check, not evidence that retrieval is solved. The scoring rules were likewise written alongside the gold outcomes they are measured against: 10/11 support labels is a regression harness, not a benchmark result. The four fixtures added in Milestone 8 were authored after the rule table was frozen and needed no rule change, which is mildly better evidence — but the same agent wrote both, with the rules in view, so it is not a held-out set in any meaningful sense.

The smoke suite gates on regressions, not on correctness

claimverifier run-suite exiting 0 means "this commit did not make the pipeline assert something its own fixtures deny, and did not change the set of claims it declines to decide." It does not mean the verdicts are right, and it certainly does not mean the claims are true. Passing --no-execute disables the gate entirely, because the gold outcomes assume the fixture scripts ran. See Results.

confidence is not a probability

VerificationResult.confidence is the share of a claim's checks that reached a pass/fail verdict — decidedness. It is not calibrated against anything, and it does not estimate the chance that the label is correct. Producing a calibrated number would need labelled data this project does not have. A claim whose only check is inconclusive scores 0.00, however confident its label sounds.

A report describes the run, not the benchmark

claimverifier report renders a claim's verdict and the evidence behind it. It never prints the task's gold outcome, and it cannot: the report is a function of the JSONL trace, and a trace records what the pipeline concluded, not what it should have concluded. Gold agreement lives in summary.csv and summary.json beside the traces, where a wrong verdict and an honest refusal to decide are counted apart. A report that scored itself would be answering a different question, and the index says so rather than tallying one.

Two smaller limits of the renderer, both stated rather than papered over. Markdown table cells escape | and collapse newlines, because an unescaped pipe silently eats a column; prose is not escaped, so a claim sentence containing * or _ renders with emphasis. That is a formatting artefact, not a correctness one — mangling p < 0.05 to defend against it would cost more than it buys. And no committed fixture is refuted by its table and undecidable from its text at once, so the report's multi-cause block is exercised by a unit test rather than by a real run.

Scoring is per-claim, and its rules are coarse in places

Each claim is scored independently; the pipeline never asks whether two claims in one bundle contradict each other. Two failure-mode mappings lose information, both deliberately: a comparison check failing (the asserted relation does not hold) is recorded as numeric_out_of_tolerance, and a code_execution check failing (the script ran but printed the wrong text) is recorded as other, since the declared expectation may be arbitrary text and the script executed fine. Both are named in docs/SCORING.md rather than hidden.

The sandbox is not a security boundary

The code-execution layer runs tiny, trusted fixture scripts committed to this repository. As shipped in Milestone 6 it copies the script to a fresh temp directory, scrubs the environment down to an allowlist, closes stdin, applies POSIX resource limits before exec, kills the whole process group on timeout, and installs an in-process guard that denies and records socket calls. Every one of those is a reproducibility control — they exist so a number a script printed came from the script rather than from the machine. None of them is isolation: there is no namespace, no seccomp filter, no chroot, no user separation. It is controlled fixture execution for reproducibility — not a production-grade or untrusted-code sandbox. Do not run untrusted code through it.

The network guard is Python-level

It patches socket inside the child's interpreter, so it covers the script, everything the script imports, and — via PYTHONPATH — any Python subprocess the script spawns, whose attempts land in the same log. It does not cover ctypes, a raw syscall, a reference captured before it installed, or a non-Python subprocess: curl has its own interpreter and needs no PATH to be found. No environment variable fixes that; a network namespace or a seccomp filter would, and this layer provides neither. The guard catches accidental network use by trusted code, and records it. It does not contain adversaries.

Reproduction is lightweight

"Reproduction" here means recomputing a statistic or running a tiny script and comparing to an expected value within tolerance. It does not attempt full environment reconstruction, dependency resolution, or long-running training.

The sandbox copies only the script, so a fixture must embed its own data; staging declared inputs is untouched work, not a hidden feature. Nothing pins the interpreter — the script runs under whichever Python invoked it, and the trace does not record the version, so two machines can disagree. Captured output is recorded verbatim apart from the sandbox path, which means a failing script's traceback embeds the host's stdlib paths: traces of failing runs are reproducible per machine, not across machines. Redacting the traceback would be worse.

No paid model in the loop by default

The default path is fully deterministic and free. Optional LLM adapters exist but are disabled; any paid-API use is gated behind dry-run, caching, a cost estimator, a hard max-cost guard, and explicit opt-in.
