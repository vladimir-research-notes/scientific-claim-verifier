Limitations

Being explicit about limits is part of the auditability goal. This system is a small, honest tool — not an oracle.

Verdicts are relative to the artifacts

Every support label and reproducibility status is relative to the supplied bundle. "Supported" means the artifacts in the task back the claim, not that the claim is true in the world. There is no universal scientific-truth judgment.

Extraction is heuristic

The default claim extractor is rule-based and deliberately simple. It targets numeric and comparison claims in clean text and will miss or mis-parse complex phrasing. It is a transparent baseline, not a state-of-the-art NLP system, and is labelled as such everywhere.

The evidence check cannot confirm a paraphrase

Deciding whether a passage asserts a claim is done lexically: verbatim containment, or every content token of the claim present with matching polarity. It has no model of morphology or synonymy — trained does not match training — so a passage that supports the claim in different words is reported inconclusive, not pass. One of the seven committed fixtures lands there, and that is the correct answer for this method rather than a bug: the alternative is to guess. Negation cues are a closed set of function words, so contractions (doesn't) are not detected, and verbatim containment is not polarity-checked. See Checks.

Fixtures are small and synthetic

Fixtures are tiny, synthetic or open datasets chosen to exercise the checks. They are not representative of real papers at scale, and results should not be read as a benchmark leaderboard. The locator conventions and the table row rule were written with the committed table fixtures in view, so a perfect linking score is a consistency check, not evidence that retrieval is solved.

The sandbox is not a security boundary

The code-execution layer runs tiny, trusted fixture scripts committed to this repository. As shipped in Milestone 5 it is a bare child process with a wall-clock timeout, closed stdin, and captured stdout/stderr/exit-code — it does not copy the script to a temp directory, scrub the environment, restrict the filesystem, or block the network (Milestone 6 adds the temp dir and the no-network policy behind the same runner protocol). Even then it provides no process-isolation or resource-limit guarantees against adversarial code. It is controlled fixture execution for reproducibility — not a production-grade or untrusted-code sandbox. Do not run untrusted code through it.

Reproduction is lightweight

"Reproduction" here means recomputing a statistic or running a tiny script and comparing to an expected value within tolerance. It does not attempt full environment reconstruction, dependency resolution, or long-running training.

No paid model in the loop by default

The default path is fully deterministic and free. Optional LLM adapters exist but are disabled; any paid-API use is gated behind dry-run, caching, a cost estimator, a hard max-cost guard, and explicit opt-in.

See also Safety for scope boundaries.
