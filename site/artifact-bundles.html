Artifact bundles

A task bundles the evidence a claim will be checked against: paper snippets, tables, figure metadata, datasets, code files, and expected outputs. Everything is small, synthetic or open, and content-hashed for provenance.

status: planned — loaders and hashing land in Milestones 1–2

Bundle components

ComponentContents
paper_text_or_snippetsPassages with stable IDs; the text the claim is drawn from.
tablesStructured tables (rows/columns) referenced by table/figure claims.
figures_metadataFigure descriptors and the data series behind them (not pixels).
datasetsSmall CSVs for statistic recomputation.
code_filesTiny Python scripts computing a reported metric.
expected_outputsGround-truth values for scoring reproduction.
metadataTask ID, provenance, licence, and notes.

Task layout

Tasks are YAML/JSON under tasks/, grouped by family; their fixture files live under data/fixtures/:

tasks/
  ml_claims/            bioinformatics_claims/    statistical_claims/
  table_claims/         code_reproduction/

data/fixtures/
  papers/     datasets/     code/     expected/

Provenance & hashing

Each PaperArtifact, DatasetArtifact, and CodeArtifact is content-hashed (artifacts/hashing.py). The hash is recorded in the trace so a report can state exactly which bytes a verdict was computed against, and a re-run against changed artifacts is detectable.

Fixture rules: small, synthetic or open, committed. No private/real papers, no large datasets, no model weights. See Safety and the repository .gitignore.

Validation

scripts/01_validate_fixtures.py (Milestone 2) checks that every task references existing artifacts, that expected outputs are present where a check needs them, and that bundles parse against the schema. The milestone runner invokes it as a between-milestone guard once it exists.
