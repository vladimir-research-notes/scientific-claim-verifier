Milestones

The system is built incrementally by an autonomous Claude Code agent driven by scripts/run_all_milestones_with_claude.sh: one milestone per claude -p run, each committed locally with docs and website updated. Guards between milestones require a new commit, a clean tree, passing tests, and (once present) valid fixtures.

Build milestones

M0 — Scaffold & project contract done

Python package skeleton (pyproject.toml, src/scientific_claim_verifier/ with __init__, cli, a schemas stub), console script claimverifier, an offline environment self-check (scripts/00_check_environment.py / claimverifier check-env), and the first CPU-only tests. Establishes a runnable, dependency-light baseline: the sole runtime dependency is pydantic; data-analysis libraries arrive with the milestones that use them. 13 tests ruff clean

M1 — Core schemas done

Typed pydantic models in schemas.py: ScientificClaim, ArtifactBundle, PaperArtifact, DatasetArtifact, CodeArtifact, EvidenceLink, VerificationCheck, VerificationResult, RunTrace, BenchmarkSuite, and the closed StrEnum vocabularies (ReproductionStatus, SupportLabel, FailureMode, and more). All models forbid unknown fields; the bundle enforces unique artifact/table/figure/passage IDs; and RunTrace.to_jsonl() is deterministic. Documented in Claim schema and docs/CLAIM_SCHEMA.md. 25 new tests 38 total ruff clean

M2 — Fixture tasks & validation done

The on-disk task format plus the code to load and validate it: a content hasher (sha256: provenance), a task loader with strict input/gold separation (the claim as authored vs. the gold extraction target), and a fixture validator reachable from both claimverifier validate-fixtures and scripts/01_validate_fixtures.py. Six small synthetic tasks span the families (numeric table, dataset statistic, evidence passage, underspecified, code reproduction, and a bioinformatics GC toy), each built on the M1 schema so the fixtures exercise the real contract. A seventh, contradicted_f1, was added in M5. Documented in docs/ARTIFACT_FORMAT.md. 28 new tests 66 total 6 fixtures valid ruff clean

M3 — Rule-based claim extraction done

The claims/ package turns the claim as authored into a populated ScientificClaim: numeric values, comparison operator, units, metrics, datasets, entities, conditions, and a deterministic normalized_claim. Transparent extractors — regexes plus small closed lexicons, labelled as heuristics — each traceable to the named rule that fired (rules_fired), so a reviewer can see why any field was populated. The rules are conservative: they leave a field empty rather than guess, because an empty field is scored underspecified downstream while a confidently wrong one is not. A per-field scorer compares each extraction to the task's gold target. Reachable via claimverifier extract-claims and scripts/02_extract_claims.py; documented in docs/EXTRACTION.md, with measured results on Results. 36 new tests 102 total 7/8 fields 6/6 conditions 5/6 ruff clean

M4 — Evidence linker done

The evidence/ package plus claims/linking.py answer where in the bundle does this claim's evidence live? Passages are found by exact verbatim lookup and ranked by a Dice keyword-overlap baseline; tables, datasets, code files, and figure series are resolved to precise locators (row=A,col=accuracy, column=value, stdout). Every EvidenceLink carries a retrieval score and the named rule that produced it. The governing rule: a link retrieves evidence, it never judges it — a table column is linked precisely when no cell matches, so a contradiction stays checkable, and a cell is linked only when the claim names the row, so an underspecified claim cannot hide inside a confident locator. A task's declared source_passage is labelled as asserted provenance, never laundered into a retrieval result; --no-declared-source runs the linker blind. Reachable via claimverifier link-evidence; documented in docs/EVIDENCE_LINKING.md, with measured results on Results. 69 new tests 171 total 12/12 gold links, blind 0 spurious ruff clean

M5 — Verification checks done

The checks/ package reads each located artifact and computes a fact about it: does the linked passage assert the claim, is the value in that table cell, does the statistic recompute from the CSV, does the fixture script print what the claim says. Tolerance is read off the claim — a value written 3.4 admits anything that rounds to 3.4 — rather than being a tuned constant. Checks report five outcomes, not two: the new inconclusive status lets a transparent lexical check faced with a paraphrase say "I cannot tell" instead of manufacturing a contradiction. A new contradicted_f1 fixture pins the project's thesis: its abstract asserts the claim verbatim while its own table refutes it, so evidence_presence passes and table_value fails, and the report keeps both. Nothing here assigns a support label — that inference is M7's. Reachable via claimverifier run-checks; documented in docs/CHECKS.md, with measured results on Results. 114 new tests 285 total 18 checks: 16 pass, 1 fail, 1 inconclusive 7 fixtures valid ruff clean

M6 — Reproducibility sandbox planned

Controlled execution for fixture code: temp dir, timeout, stdout/stderr/exit capture, no-network policy, and a trace record — landing behind the ScriptRunner protocol M5 already executes through, so no check changes. Tests use harmless fixture scripts. Not an untrusted sandbox — see Limitations.

M7 — Scoring & failure modes planned

Support-label assignment, reproducibility-status assignment, failure-mode classification, aggregate summary, and per-claim result objects.

M8 — Smoke suite planned

8–15 verification tasks run fully offline; saved run traces, results, a summary CSV/JSON, and generated reports. Drives the Results page.

M9 — Reports planned

Markdown (+ optional HTML) reports from traces: input/extracted claim, evidence, checks, support label, reproducibility status, failure mode, limitations, and a trace link.

M10 — Optional adapters planned

RecordedLLMAdapter, MockLLMAdapter, and a cost-guarded ApiAdapterStub. Disabled by default; no paid API required.

M11 — Integration contracts planned

Compatible import/export formats for the code-agent runtime, BioScientist OS, BioAgentBench, LLM regression/observability, and agent-control-bench — without depending on those repos.

M12 — Portfolio report planned

README and docs to portfolio quality: problem, architecture, worked example, smoke-suite results, reproduction commands, limitations, and the future research path.

M13 — Final cleanup planned

Run tests, lint, fixture validation, the smoke suite, and report generation; verify no secrets/private papers/large data/caches/paid-API outputs and a clean tree; commit.

Each milestone also updates this website and writes its milestone, commit, and human-review notes under docs/. Statuses here flip to done as milestones complete.
