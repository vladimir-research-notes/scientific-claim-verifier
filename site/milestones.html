Build milestones

M0 — Scaffold & project contract done

Python package skeleton (pyproject.toml, src/scientific_claim_verifier/ with __init__, cli, a schemas stub), console script claimverifier, an offline environment self-check (scripts/00_check_environment.py / claimverifier check-env), and the first CPU-only tests. Establishes a runnable, dependency-light baseline: the sole runtime dependency is pydantic; data-analysis libraries arrive with the milestones that use them. 13 tests ruff clean

M1 — Core schemas done

Typed pydantic models in schemas.py: ScientificClaim, ArtifactBundle, PaperArtifact, DatasetArtifact, CodeArtifact, EvidenceLink, VerificationCheck, VerificationResult, RunTrace, BenchmarkSuite, and the closed StrEnum vocabularies (ReproductionStatus, SupportLabel, FailureMode, and more). All models forbid unknown fields; the bundle enforces unique artifact/table/figure/passage IDs; and RunTrace.to_jsonl() is deterministic. Documented in Claim schema and docs/CLAIM_SCHEMA.md. 25 new tests 38 total ruff clean

M2 — Fixture tasks & validation done

The on-disk task format plus the code to load and validate it: a content hasher (sha256: provenance), a task loader with strict input/gold separation (the claim as authored vs. the gold extraction target), and a fixture validator reachable from both claimverifier validate-fixtures and scripts/01_validate_fixtures.py. Six small synthetic tasks span the families (numeric table, dataset statistic, evidence passage, underspecified, code reproduction, and a bioinformatics GC toy), each built on the M1 schema so the fixtures exercise the real contract. A seventh, contradicted_f1, was added in M5. Documented in docs/ARTIFACT_FORMAT.md. 28 new tests 66 total 6 fixtures valid ruff clean

M3 — Rule-based claim extraction done

The claims/ package turns the claim as authored into a populated ScientificClaim: numeric values, comparison operator, units, metrics, datasets, entities, conditions, and a deterministic normalized_claim. Transparent extractors — regexes plus small closed lexicons, labelled as heuristics — each traceable to the named rule that fired (rules_fired), so a reviewer can see why any field was populated. The rules are conservative: they leave a field empty rather than guess, because an empty field is scored underspecified downstream while a confidently wrong one is not. A per-field scorer compares each extraction to the task's gold target. Reachable via claimverifier extract-claims and scripts/02_extract_claims.py; documented in docs/EXTRACTION.md, with measured results on Results. 36 new tests 102 total 7/8 fields 6/6 conditions 5/6 ruff clean

M4 — Evidence linker done

The evidence/ package plus claims/linking.py answer where in the bundle does this claim's evidence live? Passages are found by exact verbatim lookup and ranked by a Dice keyword-overlap baseline; tables, datasets, code files, and figure series are resolved to precise locators (row=A,col=accuracy, column=value, stdout). Every EvidenceLink carries a retrieval score and the named rule that produced it. The governing rule: a link retrieves evidence, it never judges it — a table column is linked precisely when no cell matches, so a contradiction stays checkable, and a cell is linked only when the claim names the row, so an underspecified claim cannot hide inside a confident locator. A task's declared source_passage is labelled as asserted provenance, never laundered into a retrieval result; --no-declared-source runs the linker blind. Reachable via claimverifier link-evidence; documented in docs/EVIDENCE_LINKING.md, with measured results on Results. 69 new tests 171 total 12/12 gold links, blind 0 spurious ruff clean

M5 — Verification checks done

The checks/ package reads each located artifact and computes a fact about it: does the linked passage assert the claim, is the value in that table cell, does the statistic recompute from the CSV, does the fixture script print what the claim says. Tolerance is read off the claim — a value written 3.4 admits anything that rounds to 3.4 — rather than being a tuned constant. Checks report five outcomes, not two: the new inconclusive status lets a transparent lexical check faced with a paraphrase say "I cannot tell" instead of manufacturing a contradiction. A new contradicted_f1 fixture pins the project's thesis: its abstract asserts the claim verbatim while its own table refutes it, so evidence_presence passes and table_value fails, and the report keeps both. Nothing here assigns a support label — that inference is M7's. Reachable via claimverifier run-checks; documented in docs/CHECKS.md, with measured results on Results. 114 new tests 285 total at M5: 18 checks — 16 pass, 1 fail, 1 inconclusive 7 fixtures valid ruff clean

M6 — Reproducibility sandbox done

The sandbox/ package runs a fixture script under a recorded policy: a fresh temp working directory it cannot see the repository from, an environment scrubbed to an allowlist (so no host token, proxy, or PYTHONPATH reaches the child), closed stdin, POSIX resource limits applied before exec, a wall-clock timeout that kills the whole process group, and an in-process guard that makes socket calls raise — and records the attempt first, so a script that catches the exception still cannot look self-contained. Because site silently swallows errors from sitecustomize, the guard's installation is verified rather than assumed: a missing marker is a SandboxError, and the check reports error rather than attributing a number to conditions that never held. Every execution emits a JSONL trace whose first event is the policy — before the number — and two runs of one script produce byte-identical bytes, because wall-clock duration is the one value the trace omits unless asked. It landed behind the ScriptRunner protocol M5 introduced, so no verdict moved: the check table stayed 16 pass / 1 fail / 1 inconclusive. These are reproducibility controls, not isolation — see Limitations. Reachable via claimverifier run-sandbox; documented in docs/SANDBOX.md. 61 new tests 346 total at M6: 2/2 code fixtures reproduce byte-identical traces ruff clean

M7 — Scoring & failure modes done

The scoring/ package is the one stage allowed to draw an inference. It reduces each check to what it says about the claim — because a check's status is a fact about the check, and one status means more than one thing: an evidence check fails both when the passage negates the claim (refutes it) and when it never mentions it (silence is not refutation); a table check passes both when the value is in the cell the claim named (supports) and when it merely appears somewhere in a column the claim never disambiguated (ambiguous → underspecified); and a script exiting 0 with nothing declared to match is not evidence for any number. Five ordered rules then assign the support label, and each rule is recorded by name with the check IDs it read, into the report and the JSONL trace. Reading a table cell is a lookup, not a reproduction, so table claims are not_applicable rather than inflated into reproduced results. A new evidence_undecidable failure mode (schema 1.2) gives M5's inconclusive status somewhere honest to land: recording passage_does_not_assert there would publish the checker's ignorance as a fact about the paper. Over the (then seven) fixtures: 6/7 support labels, 7/7 reproduction statuses, and — the number that matters — 0 wrong verdicts, its single miss being a refusal to decide. Reachable via claimverifier verify; documented in docs/SCORING.md, with measured results on Results. 106 new tests 452 total 0 wrong verdicts 1 conservative miss byte-identical traces ruff clean

M8 — Smoke suite done

Eleven claim-verification tasks driven end to end — extraction, linking, checks, sandboxed execution, scoring — offline, on one core, in about a second and a half, writing a JSONL trace and a result JSON per task plus summary.csv, summary.json, and summary.txt. The suite is a gate, not a scoreboard, and the gate is asymmetric: any wrong verdict fails the run, while a conservative miss fails only if the set of them changed. The suite file names the standing misses and has no key for wrong verdicts, so it cannot bless one — a change that raises label accuracy by turning a claim the pipeline honestly declined to decide into one it decides wrongly has made the tool worse. The fixture set grew from seven tasks to eleven, because the original seven never produced partially_supported, approximately_reproduced, failed_numeric_mismatch, failed_environment, statistic_mismatch, passage_does_not_assert, or execution_error — seven vocabulary values with no task behind them. The four new fixtures, authored after the M7 rule table was frozen, reach them, and each landed on its hand-written gold outcome with no change to any pipeline stage. One of them, reproduce_from_predictions.py, is the first fixture that fails on purpose: a complete, working script whose data the paper never released. Reachable via claimverifier run-suite; measured on Results. 48 new tests 500 total 11 tasks · 26 checks 0 wrong verdicts gate PASS ruff clean

M9 — Reports done

Markdown (and standalone HTML) reports: the extracted claim, the evidence, each check, the inference and the named rule behind it, what remains unverifiable, and a link to the JSONL trace — in six numbered sections, so the five audit channels cannot silently merge. The report generator is a function of the trace: it imports no pipeline stage, opens no artifact, re-runs no check, and reconstructs the Milestone 7 scored claim from the JSONL bytes alone, re-validating every object against the schema on the way in. A test scores each committed fixture, writes its trace, reads it back, and asserts the reconstruction equals the original — so a fact recorded in a result but not in its trace fails the build.

Making that true required changing the trace, and SCHEMA_VERSION moved to 1.3 to say so. RunTrace.to_jsonl serializes events only, so a trace's run_id, task_id, and bundle_id previously survived nowhere but the filename; a scoring.run event now opens every stream, and scoring.claim carries the whole extracted claim. A pre-1.3 trace is refused by name, with an instruction, rather than guessed at from its path. Reachable via claimverifier report; shown on Example report. 100 new tests 600 total 11 reports from 11 traces byte-identical across run dirs ruff clean
